# 词汇悬浮卡（Vocab Overlay）

一个用 **Dart / Flutter** 编写的跨平台词汇卡片悬浮工具：主界面透明并置顶显示在其他应用之上，除右上角「设置」按钮外，鼠标与触摸事件全部穿透给下层应用。

## 功能概览

### 1. 主界面
- 全屏透明，且窗口置顶（切到后台仍显示在其他应用之上）。
- 每个词汇卡固定「上方英文、下方中文」。
- **除右上角「设置」按钮外，其余所有区域键鼠 / 触摸事件都不会被本应用截获**，会传递给下面的其他应用。
  - 桌面端通过系统级「点击穿透」（`WS_EX_TRANSPARENT`）实现；
  - 为保证「设置」按钮可点击，使用计时器轮询全局光标位置：光标进入按钮热区时临时关闭穿透，离开立即恢复。

### 2. 设置界面
- 进入设置时**先删除所有输入卡片**，再根据已有词汇卡数量与内容重建对应数量的输入卡片并填入。
- **样式**选项：切换词汇卡外观，可选「无边框（仅字体）」或「有边框」；为全局设置，作用于所有词汇卡。
- 「创建词汇」按钮：新建一张输入卡片（含两个输入框，分别标注「请输入英语」「请输入中文」）。
  - 每张输入卡片上还有：
    - **字体颜色**：点开是一个 RGB 色相环 + 饱和度/明度三角 + 透明度滑条组成的圆盘，
      调整后设置**此卡片**对应词汇卡的字体颜色（含透明度）；
    - **字体大小**：一个输入框（预填默认值 `20`），调整后设置**此卡片**对应词汇卡的
      中英文字号（中文字号取英文字号的 0.8 倍）。
- 「调整词汇位置」按钮：位于右下角「应用」按钮**之上**，点击进入调整界面。
- 「应用」按钮：点击后返回主界面，词汇卡按调整界面中设定的位置显示。
- 「退出」按钮：位于「应用」按钮**下方**，点击后会先保存当前词汇卡内容，然后退出应用。

### 3. 调整界面
- 与主界面一样大（全屏）。
- 透明且稍微变暗，鼠标 / 触摸可拖动「词汇卡」调整位置。
- 右上角「上一步」「完成」：
  - **上一步**：所有词汇卡回到本次调整之前的位置；
  - **完成**：记录词汇卡位置并返回设置界面。

### 4. 词汇卡
- 在主界面也穿透（不拦截事件）。
- **移动端只有一个绘制者**：系统悬浮窗存在时由悬浮窗引擎绘制，主界面不重复绘制
  （悬浮窗不存在时主界面兜底绘制），因此不会出现两份卡片重叠。
- 两种样式（设置界面「样式」选项切换）：
  - **有边框**：透明背景 + 黑色圆角边框；
  - **无边框（仅字体）**：只有文字，不画边框与背景。
- 字体颜色（含透明度）与字号可逐卡设置（见设置界面）；文字使用描边阴影，
  在各种背景上都清晰可读。
- 坐标统一使用**逻辑像素**（与窗口 / 渲染区域一致）；需要和原生全局光标
  （物理像素）比较时，按 `devicePixelRatio` 换算。

### 5. 存储
- 退出应用 / 点「应用」时保存：卡片数量、每张卡片的位置、英文、中文、
  字体颜色、字号（`shared_preferences`，JSON 序列化）；同时保存全局样式。
- 进入应用时读取并还原到主界面。
- 进入设置时按存储内容重建输入卡片并回填。

## 目录结构

```
lib/
├── main.dart                    # 入口、状态根、持久化编排
├── models/
│   ├── vocab_card.dart          # 词汇卡模型 + JSON 序列化（含字体颜色 / 字号）
│   └── card_style.dart          # 卡片整体样式（有边框 / 无边框）
├── services/
│   ├── storage_service.dart     # 本地持久化（卡片 + 全局样式）
│   └── overlay_service.dart     # 窗口穿透 / 置顶 / 透明 / 光标查询
├── screens/
│   ├── main_screen.dart         # 透明置顶主界面（穿透 + 设置按钮热区）
│   ├── settings_screen.dart     # 设置界面（输入卡片、样式、字体颜色 / 大小、创建、调整、应用）
│   └── adjust_screen.dart       # 调整界面（拖动卡片、上一步 / 完成）
└── widgets/
    ├── vocab_card_view.dart     # 词汇卡外观（上英文、下中文，支持两种样式）
    └── color_wheel_picker.dart  # RGB + 透明度圆盘取色器
windows/runner/                  # Windows 原生：全局光标位置通道
```

## 运行

```bash
flutter pub get
flutter run -d windows      # 桌面端（穿透、置顶、透明均完整支持）
flutter run -d <android-id> # 移动端
```

测试：

```bash
flutter test
```

## 平台能力说明（重要）

| 能力 | Windows / macOS / Linux | Android / iOS |
| --- | --- | --- |
| 透明界面 | ✅ | ✅（应用内透明） |
| 窗口置顶 | ✅ | ⚠️ 需系统悬浮窗权限 |
| 跨应用点击穿透 | ✅（除设置按钮） | ⚠️ 见下 |

- **桌面端**：`window_manager` 提供整窗穿透、置顶、透明与无边框，功能完整。
  全局光标轮询目前仅在 **Windows** 原生实现（`vocab_overlay/cursor` 通道）；
  macOS / Linux 上光标轮询返回 `null`，此时窗口保持全程穿透（设置按钮需通过其它方式唤出，可按需扩展对应原生实现）。
- **移动端**：普通 Flutter 应用无法创建「系统级穿透悬浮窗」。
  要做到真正的「跨应用悬浮 + 穿透」，需要在原生层使用 Android 的
  `TYPE_APPLICATION_OVERLAY` 悬浮窗（配合 `FLAG_NOT_TOUCHABLE` /
  `FLAG_NOT_FOCUSABLE`）或 iOS 的受限能力。本项目的业务逻辑（模型、存储、
  设置/调整界面、卡片布局）已全部与平台解耦，可直接在上述原生悬浮窗中挂载。
- **移动端卡片只有一个绘制者**：系统悬浮窗存在时，卡片由**悬浮窗引擎**
  （第二个 Flutter 引擎）绘制，主界面 `MainScreen` **不再重复绘制**自己的卡片，
  否则会出现「悬浮窗一份 + 主界面一份」两份卡片重叠；悬浮窗不存在时（首次启动、
  尚未切后台）才由主界面兜底绘制。判断依据是原生 `isActive()`，
  由 `NativeOverlay.isActive()`（`lib/services/overlay_mobile.dart`）提供。
  进入设置界面时还会把悬浮窗内容置为不可见（`setPageVisible(true)`），
  避免与设置界面里的预览重复显示。

## 关键实现点

- **穿透 + 可点按钮的矛盾**：整窗穿透后按钮也收不到事件。因此主界面用
  `Timer` 轮询全局光标，进入按钮热区时 `setIgnoreMouseEvents(false)`，
  离开时恢复 `true`。
- **调整界面的「上一步」**：进入时保存 `_original` 快照，回退时批量恢复坐标。
- **设置界面重建输入卡片**：`_rebuildFromCards` 先释放旧控制器，再按已有
  卡片重建并回填文本。
- **卡片可放到屏幕任意位置**：
  - 窗口的「无边框 + 置顶 + 铺满整个显示器」由 **Windows 原生层** 在应用启动时
    完成（`windows/runner/win32_window.cpp` 的 `MakeOverlayFullscreen()`，
    在 `main.cpp` 中调用）：去掉标题栏 / 边框、`SetWindowPos` 到当前显示器
    `rcMonitor`（完整物理区域，含任务栏）、`HWND_TOPMOST` 置顶；DPI 变化
    （换屏 / 缩放调整）时重新铺满而不是缩小。这样窗口一定是真正的全屏，
    不再依赖 Dart 侧 `setBounds`（其与显示器物理像素 / DPI 的换算不可靠，反而
    会把窗口改小 / 挪偏）。
  - Dart 侧（`OverlayService`）只负责透明、穿透与“再次确认置顶 / 无边框”，
    不再用 `setBounds` 计算坐标。
  - 不再篡改 `MediaQuery`（早期把逻辑像素改成与物理像素 1:1，会让
    `MediaQuery.size` 大于实际渲染区域，卡片被画到可视区外而看似“放不到”），
    拖动使用指针全局坐标 + 抓取偏移，边界以 `MediaQuery.size`（=整屏逻辑尺寸）
    夹取；
  - 加载到旧版本按物理像素保存的越界坐标时，自动按 `devicePixelRatio` 等比
    缩回逻辑坐标系。
- **高 DPI 光标热区**：全局光标为物理像素，主界面用 `devicePixelRatio` 换算到
  逻辑坐标后再与「设置」按钮热区比较。
